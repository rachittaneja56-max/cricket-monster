# Cricket.Monster product findings

Checked 12 November 2026 against live technical documentation and repository source. This is an implementation note for the redesign review, not a change to the approved feature scope.

## Decisions to flag, not silently resolve

| Area | Current frontend and redesign brief | Current linked technical specification | Redesign treatment |
|---|---|---|---|
| Match questions | Eight: winner, toss winner, toss decision, top scorer, top wicket-taker, most sixes, Player of the Match, final scheduled over | Five: winner, Team A run range, match wicket range, top scorer, one LLM-selected batter's run range | Preserve eight prototype questions. Production question contract needs explicit reconciliation. |
| Locking | Toss questions before toss; others before start. Current demo has a single global lock toggle. | Every answer locks at scheduled match start or when status stops being SCHEDULED | Preserve the two visible deadline groups. Label lock demonstrations as simulated; do not imply server enforcement. |
| Daily challenge | Ten questions, 180 seconds, replayable practice | Five questions, 90 seconds, one attempt per IST day; ten-second submit grace | Keep ten/180 as requested. Flag five/90 as a current source conflict. |

| Match ranking | No live scoring | Ten points each on RESOLVED questions; VOID excluded; global or per-match ranks | No fake points/leaderboard. Show truthful sample/pending results only if useful. |

## Verified prototype capabilities and gaps

- Static HTML/CSS/JavaScript, no build step. No API requests, authentication, real fixtures, live ranking or server scoring in the inspected scripts.
- Match picks save to `cm-demo-picks-v1` in localStorage; save failure has a visible status. Partial picks can be saved. Lock preview is in-memory only.
- The homepage demo is Mumbai vs Chennai, but its destination is Bengaluru vs Chennai. Home selections do not carry into the form.
- Match saved data accepts any object without checking that values belong to the visible options. A corrupted/stale value can appear in the summary and completion count.
- Quiz has ten questions; answer index keys are shipped in public JavaScript. Answers are hidden in the normal UI until completion, but this is not suitable for competitive production quiz secrecy.
- Quiz expiry uses `Date.now()` and localStorage. It can resume an attempt, and expired attempts render results. Replay is intentional practice behavior.
- Resume bug: the restore path creates an expiry-only interval. Clicking Resume calls `renderQuestion()` without replacing that interval with the normal countdown updater, leaving the visible countdown static between interactions.
- Current Match lock preview disables all answers simultaneously. It cannot demonstrate a toss-closed/match-open intermediate state.

## Current technical details relevant to future integration

The linked spec now uses five Match Monster tables and six Daily Monster tables. Match questions publish at T−48h; max four featured matches/day, with player questions on only the top two on busy days. Missing squads can reduce the question count to four team questions. Squad quality below 90% replaces the LLM batter question with Team B's total; top scorer remains with “Someone else” when squads exist. Daily questions are team-written, not generated by an LLM, with 2 easy/2 medium/1 hard, a 60-day no-repeat target, and at least 300 seed questions.

These are documentation claims about the intended backend, not verified capabilities of the frontend repository.

## Reference board: evidence and design deductions

| Reference | Directly observed evidence | Borrow conceptually | Avoid |
|---|---|---|---|
| Official IPL homepage | Clearly separated News, Videos, Photos, Matches, Points Table, Teams; featured stories; performer categories | A short sports-specific navigation vocabulary; clear distinction between match activity and editorial content | Reproducing the large publisher navigation or presenting live stats in a prototype |
| Official Mumbai Indians CSK–MI graphical preview | Downloaded and visually inspected official 592×444 graphic: yellow/blue split, large opposing team crests, central versus, single bold headline, compact date/time/venue line | Immediate team recognition; information ordered teams → action → metadata; team color in bounded areas | Full-page competing team colors; copying crests/artwork without need; dense promotional text |
| The Hundred homepage | Team picker and match entries include teams, completion status, scores, result, venue and match-centre link | Keep fixture identity, state and next action together in one component | Importing the huge fixture feed or fantasy navigation into a three-feature MVP |
| Cricbuzz homepage | Match strip, All/Live Now/Today controls, tournament/format labels and result status before news | Concise status labels and stable scorecard-like alignment | Advertising density and long news columns |
| Instagram graphics | Search did not return a directly inspectable official Instagram graphic. Official MI graphic above is a verified matchday visual reference, not evidence of a particular Instagram post | Apply the inspected matchday graphic's hierarchy to compact social cards | Claiming an Instagram-specific visual audit was completed |
| ESPNcricinfo | Direct web retrieval returned 403; accessible Cricinfo mobile search metadata was insufficient for a visual audit | No visual claim made | Claiming unseen layouts were inspected |

Suggested coherent direction: deep night navy, warm off-white, one scoreboard-yellow action accent, restrained team identity badges. Keep the stadium to a purposeful hero atmosphere and fade it into the same page color. Use compact display typography only for headings, regular readable interface text for questions and posts. These are design recommendations, not factual claims about the reference sites.
